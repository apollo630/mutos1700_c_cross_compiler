# nmmap.txt - a map of the real MUTOS 1700 nm (mutos/mutos_bin/nm.golden.base64.txt)
#
# The binary (0407, text 1ab8, data 1ab8..1c1a, BSS to 2110) is stripped; the names below are v7's
# (v7/nm/nm.c), found by the strings each function passes, the calls it makes and
# its position. It is crt0, then nm.o - v7's nm.c, its three functions -, then
# libc.a from text 0678 (fseek) (nmdis.py matches the other functions against
# libc.a's objects). nmdis.py reads this file.
#
# Format: "T <text offset> <name> <status> <port> [<note>]" for code,
#         "D <data offset> <name> [<note>]" for data.
# Status (against v7/nm/nm.c): same - compared, does what v7's does
#                                      libc - libc.a's, as far as the port re-enacts it
# Port: ported - in src/mutos_nm/nm.c, read from the text at that
#       offset (libc.a's: only where the port re-enacts what nm sees of
#       it - stdio's buffering and status values; the rest is the host's)
#
# Common to all: the headers are bytes (ar_hdr 26, exec 16, nlist 12), the
# longs have their high word first (arp.ar_size, off), the symbol's type is
# read as a word and its N_EXT bit (040) tested, FORMAT is "%04x", and arp
# and exp lie one behind the other at 1c28 and 1c42 (arp.ar_name of 14 bytes
# runs on into the header when it has no 0 - "nm: %s-- no name list" prints
# it so).
