# ccmap.txt - a map of the real MUTOS 1700 cc (mutos_bin/cc.golden.base64.txt)
#
# The binary (0407, text 8026, data 894, BSS 2776 bytes) is stripped; the
# names below are v7's (v7/cc/cc.c), found by the strings each function
# passes, the calls it makes and its position. 0407 is one segment: the
# text at 0000, the data from 1f5a, the BSS from 22d8, the heap from 2db0,
# the stack at the top - so a data address below is an address in that
# segment, not an offset in the data. It is crt0 (the 0407 crt0: jumps
# at 0000-0010, the code at 0080), then cc.o - v7's cc.c, its ten
# functions in source order -, then libc.a from text 0fc6 (ccdis.py names
# every function there by matching libc.a's objects against the text).
# ccdis.py reads this file; cctables.py --strings prints the strings.
#
# Format: "T <text offset> <name> <status> <port> [<note>]" for code,
#         "D <address> <name> [<note>]" for data.
# Status (against v7/cc/cc.c): same  - compared, does what v7's does
#                              delta - compared, v7's code with the noted changes
#                              libc  - libc.a's, as far as the port re-enacts it
# Port: ported - in src/mutos_cc/ccport/cc.c (libc.a's in cclib.c), read
#       from the text at that offset
#
# Every function was compared instruction by instruction. main()'s switch
# on the option letter is hashed (c % 5 into a jump table at 02ff, then
# c / 5 compared); idexit() is not called but passed to signal() (0c3c).
#
# ---- crt0.o

# ---- cc.o
